## Cross-config fixes (all of TP8 / EP8 / EP16)

### C1. KV-cache memory recipe — the "50K-death" fix
- **Symptom:** first ≥50K request killed the ApiServer (EngineDeadError / shm_broadcast
  "cancelled" / ApiServer exit None).
- **Root cause:** launch omitted `--kv-cache-memory-bytes`, so vLLM ran a boot profiling
  forward that OOM'd the MLA workspace at long context.
- **Fix (recipe):** `KV_CACHE_MEMORY_BYTES=60000000000` (60 GB) + `MAXLEN=131072`. Passing
  `--kv-cache-memory-bytes` skips the profiling forward.
- **Lands in PR#205:** already the default in `vllm_pd_launch.sh` (line ~53/68,
  `MEM_ARG`) and `ep16_orchestrate.sh` (`PF_KVBYTES`/`DC_KVBYTES=60e9`). Document in
  `README.MD` / `GLM52_MI355X.md` recipe block.

### C2. MTP × MoRIIO block-transfer fix — **new, upstream-worthy**
- **Symptom:** with `--speculative-config method=mtp`, KV transfer failed
  `ValueError: local_block_ids longer than remote_block_ids: N+1 > N` → decode gets no KV
  → router "No prefill servers".
- **Root cause:** MTP allocates one extra trailing (draft) KV block on prefill;
  `moriio_layout.py::compute_block_transfer_offsets` asserted local ≤ remote.
- **Fix:** truncate local to `len(remote)` (drop trailing draft block; decode recomputes)
  with `warning_once`. MoRIIO analogue of upstream vLLM **PR #46694** (NIXL connector).
- **Validated:** EP8-MTP 50K 2/2 success, write-fail 0, **TPOT 37 ms vs 60 ms MTP-off
  (~38% faster)**, **NIAH 128K 9/10** (correctness gate).
- **Lands in PR#205:** `apply_glm_dsa_moriio_mtp_blockfix.py` (idempotent, anchor-based,
  matches the repo's `apply_*.py` convention). Run in the Dockerfile after vLLM install,
  alongside the other `apply_glm_dsa_*` scripts. (Also mirrored as an NFS bind-mount for
  live runs: `patches/moriio_layout.py`.)
- **NOTE:** this is a **vLLM** fix (file lives in the vLLM tree), not a MoRI change. No
  existing upstream PR covers the MoRIIO connector; worth submitting to `vllm-project/vllm`.

### C3. Decode cudagraph + chunked-prefill config (confirm uniform, keep)
- Decode `cudagraph_mode=FULL_AND_PIECEWISE` (capture 1–256) + `use_inductor_graph_partition`;
  prefill `cudagraph_mode=NONE` (compute-bound + AITER-eager crash workaround); chunked
  prefill on (`max_num_batched_tokens=16384`); fp8 KV, block-size 1; prefix-caching off.
- **Verified identical across TP8 / EP8 / EP16** (and the MTP runs) → comparisons are
  apples-to-apples. Already encoded in both launchers; no change needed, just documented.

## EP16 2P/2D (DP16 across 2 nodes/role, MoRI-EP w/ Tej PR#558 + MoRIIO)
- **E1. Decode `GPUUTIL=0.85` (NOT 0.90) — EP16-specific fix.** MoRI shmem heaps
  (`MORI_SHMEM_HEAP_SIZE=16G` + `ROCSHMEM_HEAP_SIZE=8G` + overhead ≈ 33 GB) preallocate
  before vLLM, leaving 254.5/288 GiB free; decode `0.90` needs 259.2 GiB → `init_device`
  ValueError (masqueraded as an all2all crash for 5 attempts). Prefill `0.85` always passed.
  Fix: decode `GPUUTIL=0.85`. Landed in `ep16_orchestrate.sh` (all 4 decode drive lines).
- **E2. MODEL passthrough** in `ep16_orchestrate.sh` (was hardcoded FP8) so MXFP4 works via
  `MODEL=…/GLM-5.2-MXFP4` (quark auto-detected from config.json).
- **E3. Tej PR #558** (`MORI_EP_OVER_RDMA=1`, host-CPU doorbell proxy) + `NCCL_IB_DISABLE=1`
  + `MORI_SHMEM_HEAP_SIZE=16G` — required for cross-node all2all on ionic. Already in
  `vllm_pd_ep16_launch.sh`; bake MoRI PR#558 in the Dockerfile (already tracked).
- Uses C1 + C2 + C3. EP16 A2A both `mori_high_throughput` for bring-up.
