What changed

1. Fast prefill: ROCm/aiter#3913. The DSA sparse indexer's FP8 MQA-logits kernel on gfx942 now runs in flydsl instead of Triton, about 10× faster at 256K+ context. It is a Python-only change, cherry-picked onto the validated AITER base (it targets the same flydsl 0.2.2), so every decode kernel is unchanged. Verified bit-exact against the Triton kernel on packed multi-request batches.
2. Correctness under concurrency: MoRIIO READ step barrier (vLLM 98b24865). The decode leg's per-layer KV-read wait was skipped whenever a step replayed a FULL CUDA graph, and the worker returned early on steps with no new reads. A just-transferred request's first decode step could therefore read KV, indexer or KDA state that was still arriving. Fast prefill made that overlap common (router concurrent NIAH 91/96). The fix waits on the host for all in-flight reads before each decode forward. It holds in every graph mode and costs nothing measurable (95/96, same TTFT and TPOT).

Known limitations

  • No-MTP decode with a CUDA graph (not this configuration) misses about 25% of 16-way concurrent NIAH probes; eager decode passes, and so does this MTP + FULL_AND_PIECEWISE configuration. Without MTP, run decode eager.
  • Single-request TTFT is bound by one prefill DP rank. Wider expert parallelism (EP16) raises concurrent throughput; single-request TTFT needs tensor or context parallelism in the prefill leg.
  • vllm-project/vllm#58454 (kpool state with speculative decoding when a draft completing a pool is rejected) is not included: it needs a block size that is a multiple of 8 and changes the transferred tail layout.
