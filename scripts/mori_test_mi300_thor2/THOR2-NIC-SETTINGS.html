Broadcom Thor2 (BCM57608) — RoCE / RDMA NIC Settings MI300X + MoRI

Validated device-level (niccli) + host RoCE/NCCL/MoRI configuration for GPU-initiated RDMA (MoRI-EP / MoRI-IO) and NCCL/RCCL on AMD Instinct MI300X (gfx942) over Broadcom BCM57608 "Thor2" 400G.
The one thing to know first — Thor2 has no PCIe atomic-completer. AtomicOpsCap: 32bit- 64bit-. Any RDMA path that posts atomics into GPU VRAM (e.g. MoRI-EP's default InterNodeV1/v1 kernel, which uses AMO_ADD) will hang. Use a WRITE-based path: MoRI async_ll kernel (MORI_EP_FORCE_ASYNC_LL=1). Pure-WRITE traffic — MoRI-IO, ib_write_bw, NCCL — is unaffected.

DRANET / pod-netns note. When NICs are injected into a pod network namespace (DRANET), the benic netdevs arrive DOWN with no IP, so RoCEv2 GIDs don't form. The entrypoint must ip link set benicXp1 up + ip addr add <fabric-ip>/31 → PORT_ACTIVE and GID index 3 forms. Device names race (rocepNNsN ↔ rdmaN) — resolve the actual names from /sys/class/infiniband at runtime and set MORI_RDMA_DEVICES/NCCL_IB_HCA to those.
