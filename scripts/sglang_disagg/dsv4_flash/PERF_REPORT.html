1. Summary

DeepSeek-V4-Flash-FP8 is served through MoRI-EP wide-EP disaggregated P/D. Both topologies are validated end-to-end via sglang_router, greedy /v1/completions. Since the initial enablement, decode now runs under CUDA-graph (MoRI-LL) and the decode-latency SLO is met.

  • Correctness (NIAH): 18/18 PASS on both EP8 1P1D and EP16 2P2D — context 1K→200K, needle at 10/50/90% depth (18/18 re-confirmed with decode CUDA-graph on).
  • Decode CUDA-graph: enabled (MoRI-LL, backend=full). Prefill stays eager (MoRI-HT).
  • MTP (EAGLE speculative decode): enabled — DSV4 built-in MTP head, accept length ~3. Accuracy identical (NIAH 18/18; every draft token verified by the full model).
  • TPOT SLO (<50 ms p95): MET with margin — 100K/1.1K, p95 39–40 ms at con12/24/36 (was 49–59 ms before MTP).
  • TTFT SLO (<10 s): NOT met at 100K (~78–157 s) — compute-bound ROCm prefill wall (see §6). Holds for ISL ≲16K. (MTP is decode-only; does not affect TTFT.)

4.3 MTP (Multi-Token Prediction / EAGLE speculative decode)

DeepSeek-V4-Flash ships a single MTP head (num_nextn_predict_layers: 1). Enabled as the EAGLE draft: --speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4. The draft proposes several tokens per step; the full model verifies every one, so output is bit-identical to non-speculative decode — accuracy is unchanged.

Works on our stack: MTP + MoRI-LL + decode CUDA-graph coexist on SGLang 0.5.15 / gfx942 — no paged_mqa_logits_metadata assertion (a gap seen on some other hardware). Accept length ~3 (EP16) / ~2 (EP8).

6. TTFT at 100K — root cause & the upstream ask

During 100K prefill, GPU utilization = 100% on all ranks → compute-bound, not comm-bound. 100K × 43-layer DSV4 sparse-MLA on MI308X saturates at ~1720 tok/s → ~58 s TTFT. Two would-be accelerators are both upstream enablement gaps, not tunable config:

  • Sparse-MLA prefill kernel is CUDA-only. SGLang explicitly logs "Disabling SGLANG_OPT_FLASHMLA_SPARSE_PREFILL by default on ROCm/HIP for DeepseekV4ForCausalLM" → MI308X runs the dense fallback.
  • Prefill context-parallel conflicts with DP-attention. DSV4 requires --cp-strategy interleave, but interleave CP forbids DP-attention, and DSV4 requires DP-attention (num_key_value_heads=1). So prefill-CP is unusable for DSV4-Flash EP here.

Config levers tried (exhausted): chunk size 512→8192/rank (+9%), DSA prefill backend (0%), sparse-prefill (ROCm-blocked), prefill-CP (DSV4/DP-attn conflict).

Ask: (a) ROCm/aiter port of the sparse-MLA prefill kernel for DSV4 (biggest lever); or (b) DP-attention-compatible interleave prefill-CP for DSV4. Until then, <10 s TTFT is achievable for ISL ≲16K; 100K TTFT is a hardware/kernel ceiling on this stack.

7. What changed to reach the winning config (decode CUDA-graph + MTP)

The initial build ran decode eager because MoRI-LL crashed under CUDA-graph capture. Root-caused to two independent issues, both fixed; then MTP layered on top:

  • MoRI too old. Pinned 158c7e83 predated #363 (guard dispatch kernels vs out-of-range expert id → the low_latency_async.cpp:360 (pe>=0 && pe<worldSize) assertion) and #505 (AsyncLL slot double-alloc when top-k does not divide warpSize; DSV4 is topk6/warp64). Bumped MORI_COMMIT → 7c51d18f.
  • Recv-buffer sizing conflated with the dispatch cap. The launcher tied SGLANG_MORI_NUM_MAX_DISPATCH_TOKENS_PER_RANK (sizes the LL recv buffer) to the smaller decode dispatch cap → low_latency_async.cpp:324 "Total recv token overflow" during capture. Decoupled them (decode PER_RANK=512, prefill PER_RANK=16384), role-specific.
  • MTP enabled. DSV4-Flash's built-in MTP head as the EAGLE draft (--speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4). Works with MoRI-LL + decode CUDA-graph; accept length ~3; accuracy unchanged (NIAH 18/18). This is the largest decode-latency win (§4.3).
