Key insight: the ~150 s cost is a fixed per-decode-wave floor that is shared across all in-flight requests — 16 concurrent finish in ≈ the time of 1. Throughput scales with concurrency; the floor only hurts single-stream latency.

4 · Root-cause: the concurrency write-race

In WRITE mode, decode admits a request when the ZMQ write_done message arrives — but on RoCE, the sender's RDMA-WRITE completing does not guarantee the KV is visible in the receiver's HBM. Under concurrency, decode read stale / garbage KV.

The fix (vLLM moriio_engine._finalize_if_complete): after the writes complete and before write_done, issue a tiny RDMA read of every written region (stashed as readback_targets, capped 64). An RDMA read-after-write to the same session forces the prior writes globally visible — deterministic, vs a guessed K3_WRITE_FENCE sleep. Enabled with K3_WRITE_READBACK=1.
